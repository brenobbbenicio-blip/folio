# Fontes do agente de Pesquisa e Documentos

Consultadas em **03/10/2026**. Os seis projetos abaixo constam em `/workspace/github-starred/starred-authenticated.ndjson`. Li os trechos indicados dos READMEs publicados nas branches principais e, quando indicado, arquivos adicionais. A consulta foi por HTTP, sem instalação ou execução dos projetos.

Os textos consultados foram preservados em [fontes-pesquisa-raw](fontes-pesquisa-raw/). As branches podem mudar; esses arquivos registram a leitura feita nesta sessão. As utilidades propostas são minha avaliação; as capacidades e dependências atribuídas aos projetos vêm das fontes. Não tomei popularidade ou alegações de benchmark como validação do desempenho no material do usuário.

| Projeto e fonte lida | Utilidade concreta para o agente | Dependências, limites e licença informados na fonte |
|---|---|---|
| [PyMuPDF](https://github.com/pymupdf/PyMuPDF) — [README](https://github.com/pymupdf/PyMuPDF/blob/main/README.md), especialmente instalação, formatos, exemplos de extração/OCR, FAQ e licenciamento | Extrair texto e metadados de layout por página, localizar trechos, obter tabelas e renderizar páginas para conferir citações e OCR. | OCR usa Tesseract e precisa de dados de idioma `tessdata`; texto vazio ou caracteres corrompidos podem exigir OCR. PyMuPDF4LLM e PyMuPDF Pro são extensões distintas. Suporte Office nativo é Pro, com chave de licença; avaliação Pro sem chave limita páginas e tempo. README informa **AGPL v3** e alternativa comercial da Artifex para aplicações proprietárias. |
| [RapidOCR](https://github.com/RapidAI/RapidOCR) — [README](https://github.com/RapidAI/RapidOCR/blob/main/README.md), introdução, uso, Docker e licença | Alternativa de OCR para páginas digitalizadas e imagens, com motores de inferência distintos e possibilidade de implantação offline. | Padrão documentado reconhece **chinês e inglês**; outros idiomas dependem da lista de modelos e seleção adequada. Não presume português pronto. Exemplo Python utiliza `rapidocr` e `onnxruntime`. Código e componentes: **Apache 2.0**. README também identifica modelos derivados de PaddleOCR, titulares dos pesos e redistribuição dos artefatos aplicáveis sob Apache 2.0; fontes e atribuições específicas ficam em `MODEL_LICENSES.md`, não lido nesta consulta. |
| [Trafilatura](https://github.com/adbar/trafilatura) — [README](https://github.com/adbar/trafilatura/blob/master/README.md), introdução, recursos, exemplo e licença | Converter páginas HTML de entrevistas, artigos e críticas em texto com autor, título, data e outros metadados; exportar Markdown/JSON para uma ficha de pesquisa. | O README descreve um equilíbrio entre precisão e cobertura: extração automática pode omitir conteúdo ou incluir ruído, exigindo conferência da fonte usada. O escopo principal é HTML, com elementos como comentários, links, imagens e tabelas opcionais. Licença atual **Apache 2.0**; versões anteriores a 1.8.0 usam **GPLv3+**. |
| [PageIndex](https://github.com/VectifyAI/PageIndex) — [README](https://github.com/VectifyAI/PageIndex/blob/main/README.md), definição, quickstart, benchmarks e comparação local/cloud; [LICENSE](https://github.com/VectifyAI/PageIndex/blob/main/LICENSE) | Avaliar consulta recorrente a PDFs extensos por uma árvore de seções, preservando referências de página em uma pesquisa sobre livros ou relatórios longos. | README distingue modo **local para PDFs textuais** de Cloud, que inclui OCR/imagens e armazenamento remoto. Exemplo local ainda configura chave de fornecedor de LLM; indexação local não significa ausência de chamadas externas ao modelo. Cloud requer chave PageIndex. Benchmarks são alegações contextualizadas do projeto e não garantias para outros arquivos. Código sob **MIT**; condições do serviço Cloud não foram avaliadas. |
| [LlamaIndex](https://github.com/run-llama/llama_index) — [README](https://github.com/run-llama/llama_index/blob/main/README.md), nota atual dos mantenedores, core/integrações, overview, exemplos e persistência; [LICENSE](https://github.com/run-llama/llama_index/blob/main/LICENSE) | Avaliar uma base consultável de documentos com conectores e recuperação de contexto quando houver volume e perguntas recorrentes; separar leitura, indexação e resposta. | Framework core e integrações são pacotes distintos. Exemplos dependem de um fornecedor OpenAI ou de configuração alternativa com Ollama e embeddings HuggingFace. Por padrão, dados ficam em memória e a persistência em disco é explícita. README alerta que a documentação é atualizada com mais frequência e distingue o framework do serviço LlamaParse, que requer conta/chave. Framework sob **MIT**; não estendi essa licença aos serviços ou modelos externos. |
| [Whisper](https://github.com/openai/whisper) — [README](https://github.com/openai/whisper/blob/main/README.md), setup, modelos/idiomas, uso e licença; [model-card](https://github.com/openai/whisper/blob/main/model-card.md), uso e limitações | Referência para transcrever episódios, entrevistas ou áudio fornecido e depois produzir pauta, resumo e seleção de trechos a conferir. | Requer FFmpeg e dependências como PyTorch; modelos têm diferentes necessidades de memória. Precisão varia por idioma e sotaque; model-card registra **alucinações e repetições**. Não oferece diarização confiável como garantia, nem transcrição em tempo real pronta. README afirma que `turbo` não é treinado para tradução; tradução de fala no projeto é para inglês. Código e pesos sob **MIT**. |

## Escolha inicial

Usar leitura direta e ferramentas existentes para tarefas avulsas. Se houver necessidade de implementação: PyMuPDF atende a PDF textual; OCR atende apenas às páginas sem texto confiável; Trafilatura atende à extração de HTML. PageIndex e LlamaIndex são alternativas a avaliar quando uma coleção recorrente justificar indexação. Whisper atende à etapa de transcrição, que continua a precisar de conferência para citações. Nenhuma dessas dependências foi instalada ou testada no ambiente nesta tarefa.
